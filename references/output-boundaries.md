# 输出边界：本地预览 HTML 与 Pages

这份边界用于避免把“预览页”误解为 GitHub Pages 或网站部署能力。

## 本 Skill 负责的输出

- **公众号正文 HTML**：通过 `validate_gzh_html.py` 的纯 `<section>` 片段，供公众号编辑器粘贴或草稿 API 上传。
- **本地预览 HTML**：由 `scripts/wrap_preview.py` 生成的本地文件，只用于浏览器检查和复制正文；它可以带按钮、脚本和样式外壳，但外壳不能进入公众号正文。
- **可选源文件**：标注 Markdown、AI 变更日志、图表 JSON/SVG/PNG 和压缩后的 API HTML。

“本地预览 HTML”不代表已部署、已托管、已有公网 URL，也不代表启用了 GitHub Pages。

## 明确不负责的输出

以下请求不应触发本 Skill，也不能由它声称已完成：

- GitHub Pages / Pages 部署、静态站点、网站首页或多页面网站；
- 普通网页、落地页、Web 组件或与公众号无关的页面预览；
- 自动创建域名、托管服务、仓库 Pages 设置或线上发布地址。

这类需求应转交前端或站点发布 Skill；如果用户同时要公众号排版和 Pages 站点，先完成公众号正文，只有用户明确授权且另有站点流程时才处理站点部分。

## 用词与路由规则

1. 默认称“本地预览 HTML”，不要把它简称为“Pages”。
2. 用户只说“page/pages/网页预览”而没有公众号、微信粘贴或草稿意图时，不要猜测为公众号排版。
3. 交付说明不得写“已部署 Pages”“线上可访问”或虚构 URL；没有真实部署证据时只报告本地文件路径。
