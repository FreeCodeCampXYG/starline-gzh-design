# 触发与主题选择 · 回归用例

维护本 skill（改 description、加主题、调路由）后用这组用例核对，确保该触发时触发、不该触发时不触发、主题推荐合理。

## 正例（应触发 starline-gzh-design）

- "帮我把这篇 Markdown 做成公众号排版"
- "微信公众号文章排版"
- "gzh，这篇用 XX 主题"（XX 为 theme-index 中已注册主题）
- "把下面这篇文章转成能直接粘进公众号编辑器的 HTML"
- "这篇文章帮我排个版，发公众号用"
- "给公众号排版生成一套新主题 / 自定义风格"（→ 自定义主题生成流程）
- "按这张参考图帮我做一套公众号排版组件库"（→ 自定义主题生成流程）

## 反例（不应触发，应转其它能力）

- "帮我做一个网页落地页" → 前端/web skill
- "把内容做成 PPT" → PPT skill
- "帮我排版这个 Word 文档" → 排版对象不是公众号
- "写一篇公众号文章" → 这是写作，不是排版（先有 Markdown 才用本 skill）

## 主题选择行为（自动推荐制）

- 用户指定了 theme-index 中已注册的主题 → 直接执行不提问
- 题材有明确契合 → 单问确认「建议用 XX（理由），确认还是换一套？」，选项给推荐项 + 1~2 备选 + "看全部"，不擅自定死
- 题材无明显倾向 → 默认把 theme-index 第一行（摸鱼绿）作推荐项放第一位，让用户在几套里选
- 用户明说"直接排/一键/不用问" → 全自动例外：自动选题材最契合主题，交付时说明理由
- 用户选定主题后 → 在该主题内部按"文章类型 → 组件组合配方"匹配组件
- theme-index 为空（无已注册主题）→ 不排版，告知用户先添加主题风格，不要凭记忆编造主题

## 关键行为核对（用 assets/sample-article.md 或含代码块/图片的文跑一遍）

- [ ] 排版前写出读者任务、唯一结果、核心路径与辅助信息四行层级简报
- [ ] 封面、开场承诺与前 3 个主标题优先写读者要完成的任务，不被整理法则名称占据
- [ ] 二八、STAR、四象限等若只是整理手段，使用 11–12px 辅助说明；文章明确讲法则本身时允许升为主层级
- [ ] 选主题默认把 theme-index 第一行主题放第一位
- [ ] 解析结构后判定了文章类型，并按主题库「文章类型 → 组件组合配方」表选组件组合（不是逐段随机选）
- [ ] 点缀组件种类不超过配方表规定的上限
- [ ] 目录/导航组件位置符合主题骨架（摸鱼绿：toc-scroll 紧跟封面之下，在引言和前言之前）
- [ ] 正文引号生成时即为全角弯引号，无需事后替换
- [ ] 代码块走代码块组件，不塞进段落
- [ ] 图片用图片组件、GIF 加动图角标
- [ ] 正文半角标点被改成中文全角（代码块内不动）
- [ ] 开头引言卡署名按文章作者/主题定，不固定"甲木"
- [ ] 尾部签名区使用本次请求或项目 `DEV_STATE.md` 中已确认的公开身份；缺失时先询问，不把占位符交给用户
- [ ] 原文已有签名段时合并进唯一签名区，不重复
- [ ] 强调/小标题用小标签或左竖条，无虚线框
- [ ] 代码块紧凑：每行一个 `<p style="margin:0">`，无 `white-space:pre`，无大段空白
- [ ] `【插入…】` 类待补占位用 2c 居中板块，不是左对齐提示块
- [ ] 骨架按所选主题库的"完整文章模板骨架"装配，不套用其它主题骨架
- [ ] 公众号复制正文不含 `width:50%` 或 `flex-basis:50%`，关键关系在单列状态下仍完整
- [ ] 生成后跑 scripts/validate_gzh_html.py，ERROR 与半角 WARNING 清零

## 内容主次校准用例

- 用户说“用二八法则、STAR、乔哈里窗式四象限整理怎么做小番薯账号” → “怎么做账号”是标题、封面与章节主线；三个法则只作相关步骤的小注或文末整理说明
- 用户说“写一篇 STAR 法则入门” → STAR 本身就是核心主题，可进入标题、导读和主章节；不得机械降级
- 原稿的方法名在前、实际动作在后，用户同时要求“归纳／优化／重排” → 允许重排为行动优先，但不删除来源、不虚构案例或结论
- 用户只要求“保持原文、只排版” → 不改写事实与段落内容；仍可用字号、颜色和组件强弱让原稿中的真实核心优先
- 封面出现二八、STAR、四象限，但正文真正讲账号运营 → 回归失败；封面应改为定位、发文、承接、复盘等读者任务

## 真实公众号粘贴兼容用例

- 输入含 `display:flex;flex-wrap:wrap` 父级和 `width:50%` 子项 → `component_lint.py` 与 `validate_gzh_html.py` 必须报 ERROR
- 四象限组件 → 输出四张全宽纵向卡片；即使微信剥离父级布局样式，也不会只占左半屏
- `display:flex` 仅用于标签或单行装饰，剥离后仍能自然阅读 → 可保留，但不得出现 50% 半宽子项
- 浏览器预览正常、用户真实粘贴截图显示错位 → 以真实粘贴为准，先降级块级结构再复测，不用预览结果反驳用户

## 自定义主题生成行为

- 用户说"生成新主题"但只给一句风格描述 → 一次性问全偏好字段（不逐字段追问），空缺项按 theme-generator.md 规则自动补全
- 用户上传参考图 → 先 Read 提取视觉特征，只做风格转译，不复刻图中文字/Logo/构图
- 生成的区块库 HTML 保存到 `assets/theme-previews/{theme-id}.html`，全部区块在一页内连续排布，用户**整页一次浏览**确认风格（不逐块展示、不逐块确认），再转标准主题库
- 转换 `theme-{标识}.md` 时：补 `<span leaf="">`、去掉预览用 `id`、补齐五章节（变量表/组件/骨架/配方表/映射表）
- 新主题登记进 theme-index.md 且 `component_lint.py` 0 ERROR 后才算交付；之后"列全部主题让用户选"必须包含它
- 主题 ID 与已有主题冲突 → 提示换名或确认覆盖，不静默覆盖

## 本地图片图床用例

- Markdown 里有本地路径图 `![](./imgs/x.png)` → 排版前跑 `scripts/upload_image.py` 传图床换公网 URL，再装配；不要把本地路径写进产物
- 图片是远程 `http(s)` URL → 原样保留，不上传
- 未配置图床（无密钥）→ 脚本退出码 2；转告用户配置 image-host.md 或手动上传，不静默塞本地路径
- 同一张图重排多次 → 内容 hash 命名 + 本地缓存，不重复上传、URL 稳定

## 两阶段排版模式（`--annotate`）行为

- 用户说"先标注"/"输出标注文件"/"标记一下"/"两步排版"/"标注后再排" → 进入两阶段模式
- 用户只说"排版"/"gzh"/"公众号排版" → 仍走默认一阶段，不进入两阶段
- 阶段 1 输出 `_annotated.md`：含 frontmatter（type/theme/toc/tags/author/bio）、编号前缀、行内标记、尾部签名区；原文文字未改
- 阶段 1 `gzh_toc` 从 `##` 标题取最重要的 3 个，用原标题文字，不重写
- 阶段 1 末尾签名区：先解析 `gzh_author` 与 `gzh_bio`；缺失时暂停询问，不生成带身份占位符的可交付标注稿
- 阶段 1 完成后显示决策摘要（主题/理由/章节数/作者处理），等用户确认或修正
- 阶段 2 读取 `_annotated.md`，**不推断** type/theme/toc——全从 frontmatter 取
- 阶段 2 读到 `## 01` 编号就照搬，不重算；读到 `++` 就下划线组件，不重新找关键词
- 阶段 2 渲染完成后注明"由标注文件经机械翻译生成，未分析/推断"
- 修改 `_annotated.md` 的 `gzh_theme` 后重跑阶段 2 → 换主题不重分析
- 修改 `_annotated.md` 里的标记（增删 `++`/`==`/`**`）后重跑阶段 2 → 标注修正生效
- 全自动模式 + "--annotate" → 阶段 1 自动跑完，阶段 2 等用户确认
- 标注文件与原稿的 diff 只有 frontmatter、编号前缀、标记语法、尾部签名区——原文文字一个不改

## 发布身份行为

- 项目 `DEV_STATE.md` 已有完整“公众号发布身份” → 直接复用，不再次提问
- `DEV_STATE.md` 缺失或两项不完整 → 一次询问“公众号署名 + 一句话简介”，得到确认后写回固定段
- 用户说“直接排 / 一键 / 不用问”，但发布身份缺失 → 仍暂停询问；全自动模式不能绕过发布身份硬门
- 用户明确要求匿名发布 → 省略作者介绍区，不询问、不虚构、也不把匿名当作默认偏好写入
- 公开仓库场景 → 只保存用户确认可公开的署名与简介；邮箱、手机号、微信号、Cookie、Token 等不得写入
- 本次请求明确提供新署名或简介 → 本次值优先，并同步更新项目 `DEV_STATE.md`
- 最终 HTML 出现 `{{作者名}}`、`{{一句话简介}}`、`{{简介}}` 或 `{{作者身份}}` → `validate_gzh_html.py` 必须报 ERROR，不能称为“可直接发布”

## 格式兼容用例

- 给 `.docx` → 先跑 `scripts/extract_docx.py` 转 md，再结构确认，不直接读二进制
- 给 `.pdf` → Read 分页读取，删页眉页脚页码、合并硬断行，图位留居中占位
- 给无标记 `.txt`（含"一、二、"式标题）→ 正确推断为 `##`，结构确认后再排
- 给完全无标题的纯文本 + "直接排" → 全自动：语义分章 + 自拟标题 + 自选主题，交付附决策说明
- 给 `.doc` 老格式 → 提示另存为 .docx，不硬解析

## 维护 · 可验证循环

改了组件库或 SKILL 后，按这个闭环验证，确保不引入排版反模式（大空白、左对齐占位、正文虚线框、平台禁用项）：

1. **改** 组件库 / SKILL / 脚本
2. **源头关**：`python3 scripts/component_lint.py .`
   扫所有组件库的 ```html 块，检测 `white-space:pre`（大空白）、四周虚线框 `border:…dashed`（正文，居中占位块豁免）、平台禁用项（div/class/id/style/grid/position/var/@media）。须 **0 ERROR**。
3. **生成** 用改后的 skill 排版 `assets/sample-article.md`（或真实文章）
4. **产物关**：`python3 scripts/validate_gzh_html.py <产物.html>`
   检测禁用标签、`<span leaf>` 包裹、半角标点。须 **0 ERROR、半角 0 WARN**。
5. 任一关不过 → 回第 1 步，直到两关全绿。

两脚本分工：`component_lint` 管「组件库源头不含反模式」，`validate_gzh_html` 管「最终产物合规」。源头干净 → 产物必然跟着干净，这是循环成立的依据。
